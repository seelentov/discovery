# Протоколы и тестовый стенд

Многопротокольный стенд реализуется отдельно вместе с задачей по протоколам. Этот skill не создаёт его и не задаёт вымышленные команды запуска. Старый devicefarm удалён; ссылки на него в live-тестах не означают доступный стенд.

## Область проверки

ICMP (Ping), SNMP, TCP, UDP, HTTP, HTTPS, FTP, SFTP, DNS, IMAP, POP3, SMTP, Email roundtrip (SMTP + IMAP/POP3), SSH, Traceroute (ICMP/UDP/TCP), DHCP, LDAP, RADIUS, WMI, SMB/CIFS (Samba), LLDP, CDP, SNMP Traps, Syslog, NetFlow, IPFIX, IP SLA.

Это целевой перечень, а не статус реализации. Контракты и доступность каждого протокола проверяй в текущей ветке.

## Подключение стенда

Когда стенд появится, найди его документацию и реальные команды. Для выбранного протокола установи: способ запуска/остановки и readiness, адреса/порты, credentials, управление ответами и отказами, сброс данных и изоляцию экземпляров. Если этого нет — явно сообщи непроверенные сценарии; не запускай чужое оборудование вместо стенда.

По завершении задачи стенда обнови этот skill ссылками на существующие компоненты и команды. Не копируй их реализацию в skill.

## Контракт проверки

- Для каждого протокола сопоставь компонент стенда, ожидаемый результат, Unit и E2E-сценарии. Норма, таймаут, неверный ответ, потеря связи и восстановление обязательны там, где применимы; добавь ошибки авторизации/TLS для соответствующих протоколов.
- Polling: запрос действительно дошёл до сервиса, ответ преобразован правильно, результат сохранён и виден в UI. Ingestion: переданное событие/поток принят, разобран и отображён с корректными полями.
- Email roundtrip: подтвердить отправку и получение именно тестового письма с ограниченным временем ожидания и очисткой.
- Traceroute: управляемый маршрут и ожидаемые hops для каждого режима. DHCP/LLDP/CDP могут требовать отдельного L2-сегмента; сначала выясни, откуда Discovery получает данные, включая SNMP для соседей.
- WMI проверяй на Windows. Samba подтверждает свой сценарий SMB, но не все особенности Windows. Для IP SLA выясни, читаются ли результаты устройства или выполняются измерения.
- Unit использует воспроизводимые fixtures/fakes и проверяет парсинг/логику ошибок. E2E использует настоящий Discovery и управляемый сервис/генератор. Отдельно отмечай симуляцию и совместимость с реальным устройством.
- Порты, сети, данные и процессы принадлежат конкретной задаче. По окончании освобождай только её ресурсы.

Полный регрессионный прогон — по `discovery-test`; UI-проверки — по `discovery-e2e`. Недоступный стенд оставляет соответствующий E2E непроверенным.
