# Тестирование Discovery

Сначала сопоставь изменяемое поведение со сценариями: нормальный результат, ошибки, границы и восстановление. Для каждого нового сценария укажи Unit и E2E-проверку. Для bugfix воспроизведи исходный сбой тестом. Полнота означает все новые сценарии, а не только процент строк.

- Unit обычно рядом с Rust-кодом (`#[cfg(test)]`); интеграционные проверки — `crates/<crate>/tests/`. Имя Cargo-пакета бери из его `Cargo.toml`.
- Во время работы запускай адресные проверки: `cargo test -p <package> <filter>`. До Cargo-команд собери frontend по `discovery-run`.
- Финальная регрессия: из корня `cargo test --workspace --locked`, затем полный Playwright-набор по `discovery-e2e`. Не заменяй весь прогон одним изменённым spec.
- Для фронтенда: `npm run build`, `npm run lint`. Frontend Unit runner пока не объявлен; при добавлении клиентской логики настрой его и проверь её отдельно. E2E не заменяет Unit.
- Найди относящиеся к задаче `#[ignore]` через `rg -n '#\[ignore' crates`. Прочитай условия конкретного теста; только с подготовленным окружением запускай `cargo test -p <package> <filter> -- --ignored`. Не запускай все live-тесты вслепую против чужих сервисов.
- Недоступные внешние сервисы, пропуски, flaky и существующие падения перечисляй отдельно. Не объявляй всю регрессию зелёной по числу passed при пропущенных обязательных сценариях.
- После исправления причины повтори затронутые проверки; при новом изменении кода финальная регрессия должна относиться к итоговому состоянию.

Отчёт в чате: Unit — команды/результат; E2E — команды/результат; непроверенные сценарии и причины. Для документации оба уровня неприменимы, продуктовые тесты не запускаются. Для сборочных правок проверяй соответствующую сборку/manifest; отсутствие нового поведения не требует искусственных поведенческих тестов.

## Точечные команды

Из корня worktree, после подготовки UI:

```bash
cargo test -p <package> --locked
cargo test -p <package> --locked <filter> -- --list
cargo test -p <package> --locked <полный-путь-теста> -- --exact
cargo test -p <package> --locked --test <имя-файла-без-rs> <filter>
```

Первая команда проверяет пакет; остальные помогают выбрать точный тест или отдельный интеграционный target. Фильтр Cargo — подстрока, а `--exact` требует полного имени: проверяй, что выбранные тесты действительно запустились. Ноль выполненных тестов не подтверждает поведение. `-- --nocapture` добавляй только при необходимости диагностического вывода.
