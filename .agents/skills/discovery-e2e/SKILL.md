# Playwright E2E

Источники: `crates/web/frontend/playwright.config.ts`, `e2e/global-setup.ts`, `e2e/global-teardown.ts`, `e2e/fixtures.ts`.

## Запуск

1. В frontend: `npm ci`, `npm run build`, `npx playwright install chromium` (если браузер не установлен).
2. В корне: `cargo build -p discovery-agent --locked`.
3. В frontend: `E2E_PORT=<свободный-порт> npm run test:e2e`.

`E2E_PORT` должен быть числом и отличаться от портов других задач. Setup ожидает строго `target/debug/discovery-agent`: другой `CARGO_TARGET_DIR`, release-бинарник или Windows `.exe` текущий setup не подхватывает. Не заявляй Windows E2E без адаптации и прогона.

Setup создаёт scratch-каталог, memory storage, пароль администратора и выполняет обязательную смену пароля через API. Артефакты авторизации и PID лежат в `e2e/.auth` внутри worktree. Поэтому один worktree — один одновременный прогон.

## Сценарии

- Оставляй `workers: 1`, `fullyParallel: false`: specs с числовыми префиксами создают данные для следующих specs. Адресный `npm run test:e2e -- <spec>` допустим лишь при обеспеченных предусловиях; окончательная проверка — весь набор.
- Используй fixture `adminPage` и helpers из `e2e/fixtures.ts`. Для нового независимого сценария создавай собственные данные, не полагайся на случайный порядок.
- Проверяй наблюдаемый результат после действий пользователя: сохранение, повторное открытие, права доступа, ошибки. Для сетевого функционала ожидай реальный результат от стенда; mock API не доказывает работу протокола.
- При REST-подготовке данных явно проверь авторизацию request context; не считай браузерный вход доказательством доступа любого отдельного HTTP-клиента.
- Не используй произвольные sleep вместо ожидания конкретного состояния. Не ослабляй проверки ради прохождения.

## Диагностика

HTML-отчёт: `npm run test:e2e:report`. Скриншоты, trace и видео сохраняются при падении; пути смотри в выводе Playwright и `test-results`. Trace открывай `npx playwright show-trace <путь-к-trace.zip>`.

Teardown удаляет scratch и credentials. Нужные диагностические данные сохрани до очистки, исключая секреты. После аварии проверяй владельца PID перед остановкой процесса. Отчёт и trace не коммить.

## Точечный выбор сценария

Из `crates/web/frontend` после сборки UI и backend:

```bash
npm run test:e2e -- <spec> --list
E2E_PORT=<свободный-порт> npm run test:e2e -- <spec>
E2E_PORT=<свободный-порт> npm run test:e2e -- <spec> --grep '<название-теста>'
```

`--list` проверяет выбор, но не выполняет сценарий. `--grep` принимает регулярное выражение. Перед узким прогоном проверь `beforeAll`/fixtures и зависимости от предыдущих specs: при необходимости включи подготовительные specs или подготовь данные через авторизованный API. Не считай падение из-за отсутствующих данных продуктовой регрессией без проверки предусловий; полный финальный прогон остаётся обязательным.
