# Топология

Разные провайдеры видят соседство устройств по-разному: где-то это LLDP/CDP, где-то —
таблица MAC-адресов, где-то — просто договорённость об именовании устройств. Вместо того
чтобы жёстко зашивать один протокол, discovery даёт настраиваемый механизм: вы (или
интегратор при внедрении) описываете **правило** — как устройство называет себя и кого оно
считает своим соседом — на основе уже опрашиваемых метрик, а discovery сам строит и
поддерживает граф связей.

## Как устроено правило

Правило состоит из двух выражений, каждое из которых смотрит на факты и метрики одного
устройства:

- **Свой идентификатор** — как устройству называть себя в терминах этого правила.
  Например, если вы опрашиваете LLDP-таблицу устройства, это может быть его
  `lldp_chassis_id`.
- **Заявленные соседи** (необязательно) — список идентификаторов, которых устройство само
  видит рядом с собой. Например, список `chassis_id` всех записей в его LLDP-таблице
  соседей.

Если два устройства взаимно ссылаются друг на друга такими идентификаторами — discovery
считает их связанными. Правило может не задавать список соседей вовсе — тогда оно просто
группирует устройства по общему идентификатору (например, по общему сегменту сети),
без утверждения "кто с кем физически соединён".

## Когда пересчитывается связь

Не по расписанию, а сразу после того, как у устройства обновилась метрика, от которой
зависит правило — discovery отслеживает это автоматически. Обновление затрагивает только
само устройство: если сосед на другом конце связи ещё не был опрошен, связь появится сама,
как только он тоже будет опрошен — повторно опрашивать первое устройство для этого не
нужно.

## Что видно в дашборде

Раздел «Топология» — список правил (создание, редактирование, включение/выключение) и
таблица уже найденных связей для выбранного правила: пара устройств и статус — «подтверждено»
(обе стороны видят друг друга) или «одностороннее» (пока видит только одна сторона — это
нормальное переходное состояние, не ошибка).

Таблица связей — поиск по IP любого из двух устройств пары, фильтры по статусу
(подтверждено/одностороннее) и по тому, определено ли направление (аплинк/даунстрим) или
нет, сортируемые заголовки столбцов, пагинация. Период автообновления — от «без
автообновления» до раза в секунду (по умолчанию — без автообновления), тот же выбор, что на
страницах [Устройств](devices.md) и [Тревог](alerts.md).

Соседей одного конкретного устройства по всем правилам сразу удобнее смотреть прямо со
страницы [Устройства](devices.md#действия-в-конце-строки) — кнопка «Топологические
соседи» на строке устройства, без перехода в этот раздел.

## Направление — кто чей аплинк

Помимо самого факта связи, правило может (необязательно) задать третье выражение —
числовой «ранг» устройства (меньше = ближе к ядру сети/аплинк). Для уже найденной связи
между двумя устройствами discovery сравнивает их ранги и определяет направление: кто из
двоих выше по иерархии. Если ранг не задан правилом, или обе стороны получили одинаковый
ранг — направление остаётся неопределённым, но не выдумывается. Для устройств без
достаточно дисциплинированных данных для автоматики направление можно задать вручную на
конкретной связи прямо в дашборде — эта ручная настройка всегда побеждает автоматический
ранг.

Направление — то, на чём строится [подавление групповых тревог](group-alerts.md): discovery
понимает, что авария на даунстрим-устройстве может быть следствием аварии на его аплинке,
а не независимым инцидентом.

## Ограничения текущей версии

Правила (включая ранг) пишутся на встроенном языке выражений (том же, что используется для
условий тревог) — предполагается, что их настраивает интегратор при внедрении или
технически подкованный администратор, не конечный оператор NOC.
## LLDP/CDP

Отдельного встроенного LLDP/CDP-сканера нет: эти данные собираются обычными SNMP table
метриками профиля, после чего topology rule извлекает из строк local/remote port, chassis
или device ID, management address и описание соседа. Сопоставление сохраняет обе стороны,
если они доступны, не создаёт дубликаты при изменении порядка строк и удаляет устаревшую
связь после исчезновения соседа.

Повторный discovery заменяет claims атомарно, поэтому изменение порядка таблицы не меняет
идентичность связи. Неполные поля допустимы: связь показывается с теми атрибутами, которые
устройство реально сообщило.
